1. Introduction

1.1 Purpose

This document defines the software requirements for the SMS Service module. It handles SMS delivery logging, tracking, and audit trail for verification messages.

1.2 Scope

SMS delivery logging, status tracking, provider integration (Twilio), and delivery confirmation webhook.

1.3 Module Dependencies

Depends on: AUTH module (receives verification events via RabbitMQ).

3. Functional Requirements

3.1 UC-01: Process SMS Verification

FieldValue
Requirement IDsSMS-FR-001
ActorSystem (RabbitMQ consumer)
PreconditionVerification event received from AUTH module
PostconditionSMS sent via Twilio, delivery logged to sms_logs

Main Flow

  1. SMS Worker consumes event from verification.sms queue
  2. Worker extracts: userId, phone, otp, verificationId
  3. Worker sends SMS via Twilio API
  4. Worker logs delivery to sms_logs (status: sent)
  5. On delivery confirmation: update sms_logs (status: delivered)

3.2 UC-02: Log SMS Delivery

FieldValue
Requirement IDsSMS-FR-002
ActorSystem

3.3 UC-03: Handle SMS Failure

FieldValue
Requirement IDsSMS-FR-003
ActorSystem

Main Flow

  1. If Twilio returns error: log failure to sms_logs (status: failed)
  2. Route message to RabbitMQ dead-letter queue for retry
  3. Increment retry_count in sms_logs
