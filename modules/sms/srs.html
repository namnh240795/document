1. Introduction

1.1 Purpose

This document defines the software requirements for the SMS Service module of the Authentication System.

1.2 Scope

The SMS Service module handles:

  • Sending SMS OTP for verification and password reset
  • Verifying OTP codes
  • SMS delivery logging and tracking
  • Audit trail for all SMS operations

1.3 Module Dependencies

Depends on: AUTH (receives verification events from AUTH module)

4. Use Cases

UC-01: Send and Verify OTP

AspectDescription
ActorAUTH module (service-to-service), End user
PreconditionsUser has registered phone number; AUTH module requests SMS
Main Flow1. AUTH module publishes verification.requested event to RabbitMQ
2. SMS consumer receives event
3. System generates OTP code (6 digits, 5min expiry)
4. System creates SMS log record (status: pending)
5. System sends SMS via Twilio provider
6. System updates log (status: sent)
7. User receives OTP on phone
8. User submits OTP to AUTH module
9. SMS service verifies OTP against log record
Alternative Flows5a. Twilio fails → System updates log (status: failed, error_message)
5b. Retry up to 3 times with exponential backoff
9a. OTP expired → System returns 422 OTP_EXPIRED
9b. OTP invalid → System returns 422 OTP_INVALID
PostconditionsSMS log created with delivery status; OTP verified or failed
Related FRFR-001, FR-002

UC-02: Track SMS Delivery

AspectDescription
ActorTwilio (webhook), Admin user
PreconditionsSMS has been sent via Twilio
Main Flow1. Twilio sends delivery status callback to /webhooks/sms/delivered
2. System receives webhook with MessageSid and status
3. System finds SMS log by provider_message_id
4. System updates log with delivery status and delivered_at timestamp
5. System sends verification.delivered event back to AUTH module
6. Admin can query SMS status via GET /sms/:id/status
Alternative Flows2a. Invalid webhook signature → System returns 401
3a. SMS log not found → System returns 404
4a. Delivery failed → System updates log with error_message
PostconditionsSMS log updated with final delivery status; AUTH notified
Related FRFR-003, FR-004
