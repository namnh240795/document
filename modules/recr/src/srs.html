1. Introduction

1.1 Purpose

This document defines the software requirements for the Recruitment module of the HR Management System.

1.2 Scope

The Recruitment module manages the end-to-end hiring process with three distinct user roles: Candidate (job seekers), HR (recruitment team), and Employer (companies posting jobs). Each role has specific permissions and workflows.

3. Detailed Use Case Specifications

3.1 UC-01: Register Account

FieldDescription
Use Case IDUC-01
NameRegister Account
ActorCandidate, Employer
PreconditionUser is not logged in
PostconditionUser account created, JWT token issued
TriggerUser clicks "Register" button

Main Flow:

  1. User navigates to registration page
  2. User enters email, password, full name, phone
  3. User selects role (Candidate or Employer)
  4. If Employer: user enters company name, industry, company size
  5. System validates input data
  6. System checks email availability
  7. System hashes password and creates user record with role
  8. System creates profile (candidate or employer)
  9. System generates JWT token with role claim
  10. System returns success response

AUTH Module Dependency:

  • Steps 5-7 (validate, check email, hash password, create user with role) are handled by AUTH module (FR-001)
  • Role is passed from RECR to AUTH during registration
  • AUTH stores role in auth_users and includes it in JWT token
  • AUTH returns user_id and JWT token (with role) to RECR
  • RECR then creates recruitment-specific profile (candidate or employer) and links to auth user

Subscription Note:

  • All roles (Candidate, HR, Employer) can optionally purchase subscription
  • Subscription provides premium features but is not required for basic functionality
  • See UC-03: Purchase Subscription for details

Alternative Flows:

  • 4a. Email already exists: System returns error "Email already registered"
  • 4b. Invalid input: System returns validation error with details

3.2 UC-02: Login

FieldDescription
Use Case IDUC-02
NameLogin
ActorAll (Candidate, HR, Employer)
PreconditionUser has registered account
PostconditionUser authenticated, JWT token issued
TriggerUser clicks "Login" button

Main Flow:

  1. User enters email and password
  2. System validates input
  3. System checks email exists
  4. System verifies password hash
  5. System checks account is active
  6. System generates JWT token with role claim
  7. System returns token and role
  8. Frontend redirects to role-specific dashboard

AUTH Module Dependency:

  • Steps 2-6 (validate, check email, verify password, check active, generate JWT) are handled by AUTH module (FR-002)
  • AUTH reads role from auth_users table (stored during registration in UC-01)
  • AUTH returns JWT token with role claim to RECR
  • RECR uses role claim to redirect to appropriate dashboard (Candidate/HR/Employer)

3.3 UC-03: Purchase Subscription

FieldDescription
Use Case IDUC-03
NamePurchase Subscription
ActorAll (Candidate, HR, Employer)
PreconditionUser is logged in, no active subscription
PostconditionSubscription activated, user can access premium features
TriggerUser clicks "Subscribe"

Main Flow:

  1. User navigates to subscription page
  2. System displays available plans:
    • 1 Month: Standard price
    • 6 Months: 10% discount
    • 1 Year: 2 months free (pay for 10 months)
  3. User selects a plan
  4. System calculates final price with discount
  5. User reviews order summary
  6. User completes payment
  7. System creates subscription record
  8. System activates subscription
  9. User receives confirmation
  10. User can now access premium features (varies by role)

Subscription Benefits by Role:

  • Candidate: Priority application, profile boost, advanced analytics
  • HR: Advanced recruitment tools, priority support, enhanced analytics
  • Employer: Premium job posting, featured listings, advanced applicant tracking

Alternative Flows:

  • 7a. Payment failed: System shows error, subscription not activated
  • 7b. Payment cancelled: System returns to plan selection

NameManage Subscription
ActorEmployer

  5. System updates subscription record

Use Case IDUC-11
NamePost Job
ActorHR, Employer
PreconditionUser is logged in
PostconditionJob created and submitted for approval
TriggerUser clicks "Create New Job"

Main Flow:

  2. User enters job details (title, description, department, location)

NameReview Job
ActorCandidate

  • 2a. Already reviewed: System shows "You've already reviewed this job" message
