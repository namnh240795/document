1. Introduction

1.1 Purpose

This document defines the software requirements for the Recruitment module of the HR Management System.

1.2 Scope

The Recruitment module manages the end-to-end hiring process with three distinct user roles: Candidate (job seekers), HR (recruitment team), and Employer (companies posting jobs). Each role has specific permissions and workflows.

3. Detailed Use Case Specifications

3.1 UC-01: Register Account

FieldDescription
Use Case IDUC-01
NameRegister Account
ActorCandidate, Employer
PreconditionUser is not logged in
PostconditionUser account created, JWT token issued
TriggerUser clicks "Register" button

Main Flow:

  1. User navigates to registration page
  2. User enters email, password, full name, phone
  3. User selects role (Candidate or Employer)
  4. If Employer: user enters company name, industry, company size
  5. System validates input data
  6. System checks email availability
  7. System hashes password and creates user record
  8. System creates profile (candidate or employer)
  9. System generates JWT token
  10. System returns success response

AUTH Module Dependency:

  • Steps 5-6 (validate, check email, hash password, create user) are handled by AUTH module (FR-001)
  • AUTH returns user_id and JWT token to RECR
  • RECR then creates recruitment-specific profile (candidate or employer) and links to auth user

Alternative Flows:

  • 4a. Email already exists: System returns error "Email already registered"
  • 4b. Invalid input: System returns validation error with details

3.4 UC-04: Submit Application

FieldDescription
Use Case IDUC-04
NameSubmit Application
ActorCandidate
PreconditionCandidate is logged in, job exists
PostconditionApplication created, employer notified
TriggerCandidate clicks "Apply" on job listing

Main Flow:

  1. Candidate selects job and clicks "Apply"
  2. Candidate uploads resume (PDF/DOCX, max 10MB)
  3. Candidate enters cover letter
  4. Candidate reviews and submits application
  5. System validates application
  6. System checks for duplicate application
  7. System creates application record
  8. System sends notification to employer
  9. Candidate sees success message

Alternative Flows:

  • 6a. Already applied: System shows "Already Applied" error
  • 5a. Invalid input: System shows validation error
