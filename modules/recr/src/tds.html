2. Architecture

2.1 Architecture Overview

Figure 1: System Context

2.2 Key Design Decisions

#DecisionRationaleResolves
1Subscription is optional for all roles All users (Candidate, HR, Employer) can purchase subscription for premium features, but it's not required for basic functionality. FR-023
2Separate subscription_plans and subscriptions tables Plans are static configuration, subscriptions are user-specific. Separation allows plan updates without affecting existing subscriptions. FR-022
3Store final_price in subscription_plans Pre-calculated price avoids runtime discount calculation errors and provides audit trail. FR-022
4Subscription history table for audit trail Tracks all subscription changes (renewal, upgrade, cancellation) for compliance and debugging. FR-027
5Unique constraint on active subscription per user Ensures one user cannot have multiple active subscriptions simultaneously. FR-024
6Role-specific premium features Different subscription benefits for each role (Candidate: priority application, HR: advanced tools, Employer: premium posting). FR-022
7JSONB features field in plans Flexible feature list allows plan differentiation without schema changes. FR-022

6.1 Subscription Benefits (Optional)

Subscription provides premium features but is not required for basic functionality:

  • Candidate: Priority application processing, profile boost in search results
  • HR: Advanced recruitment analytics, priority support
  • Employer: Featured job listings, premium analytics dashboard
