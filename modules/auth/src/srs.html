1. Giới thiệu

1.1 Mục đích

This document defines the software requirements for the Authentication module of the Hệ thống Xác thực.

1.2 Phạm vi

Module Xác thực xử lý:

  • Đăng ký người dùng bằng email hoặc số điện thoại + mật khẩu
  • Đăng nhập bằng email hoặc số điện thoại + mật khẩu
  • Quản lý phiên và token (access + refresh token)
  • Xác minh tài khoản qua email và SMS
  • Đặt lại mật khẩu qua email hoặc số điện thoại/OTP
  • Kiểm soát truy cập dựa trên vai trò (RBAC)
  • Quản lý người dùng (admin CRUD)

1.3 Phụ thuộc Module

ModuleLoại phụ thuộcMô tả
SMSAsync (RabbitMQ)Gửi SMS xác minh qua module SMS
EMAILAsync (RabbitMQ)Gửi email xác minh/đặt lại qua module EMAIL
LOGAsync (RabbitMQ)Gửi sự kiện xác thực đến module Logger

4.1 UC-01: Đăng ký Người dùng

Khía cạnhMô tả
ActorKhách (chưa xác thực)
Điều kiện tiên quyếtNgười dùng chưa đăng nhập; user does not have an existing account
Luồng Chính1. Người dùng điều hướng đến trang đăng ký
2. Nhập tên, email và mật khẩu
3. Hệ thống kiểm tra dữ liệu đầu vào (email format, password strength)
4. Hệ thống tạo tài khoản người dùng with hashed password and assigns user system role
5. Hệ thống gửi email xác minh via EMAIL module
6. Hệ thống trả về phản hồi thành công with user ID and JWT token
Luồng Thay thế3a. Email đã tồn tại → System returns 409 Conflict
3b. Mật khẩu quá yếu → System returns 400 Validation Error
5a. Verification service unavailable → Account created, verification queued
Hậu điều kiệnUser account created with user role (unverified); verification email sent; JWT token issued
FR Liên quanFR-001

Các vai trò có thể tự đăng ký:

RoleMô tả
userTài khoản người dùng tiêu chuẩn (mặc định). Người dùng có thể tạo tổ chức và nhận các vai trò cấp tổ chức (HR, Ứng viên, Nhà tuyển dụng).

Lưu ý: super_admin accounts cannot be self-registered. They must be created by an admin via POST /admin/create-user.

4.17 UC-17: Quản lý Lời mời

Khía cạnhMô tả
ActorAdmin tổ chức / Người dùng được mời
Điều kiện tiên quyếtAdmin is logged in; invitee has email address
Luồng Chính1. Mời người dùng qua email với vai trò và nhóm (tùy chọn)
2. Hệ thống tạo token ngẫu nhiên (crypto.randomBytes(32)), computes SHA-256 hash
3. Chỉ lưu hash in auth_invitations (token_hash column)
4. Tạo URL lời mời: {FRONTEND_DOMAIN}/invitations/verify?token={raw_token}
5. Gửi email lời mời via EMAIL module with the invite URL
6. Nhận email, nhấp liên kết lời mời
7. Invitee's browser calls GET /organization/verify-invitation?token={raw_token} (public)
8. Hash token, tìm kiếm theo hash, returns validity status
9. Chấp nhận hoặc từ chối lời mời
Luồng Thay thế2a. Lời mời đang chờ trùng lặp (same email + role) → System returns 409 Conflict
8a. Token hết hạn → System auto-updates status to EXPIRED, returns 410
8b. Lời mời đã được chấp nhận → System returns status "accepted"
8c. Lời mời đã thu hồi → System returns status "revoked"
Hậu điều kiệnLời mời đã gửi với token bảo mật; user added to organization (if accepted)
