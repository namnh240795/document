6.6 Invitation Flow

Activity Diagram

See SRS Section 4.17 UC-17: Invitation Management for the invitation activity flow.

Sequence Diagram

Invitation flow involves AUTH → EMAIL (async via RabbitMQ) → Frontend → AUTH (verify/accept).

  1. Admin calls POST /organization/invite-member → AUTH generates token, stores hash, emits event
  2. EMAIL module consumes event, sends invitation email with raw token in URL
  3. Invitee clicks link → Frontend calls GET /organization/verify-invitation?token=... (public)
  4. AUTH hashes token, validates, returns status
  5. Invitee accepts → POST /organization/accept-invitation → AUTH updates status, emits event

Token Security Design

AspectImplementation
Token Generationcrypto.randomBytes(32).toString('hex') — 64-char hex string
StorageOnly SHA-256 hash stored in token_hash column (UNIQUE constraint)
DeliveryRaw token in URL: {FRONTEND_DOMAIN}/invitations/verify?token={rawToken}
Expiry72 hours (configurable via INVITATION_EXPIRY_HOURS)
ResendGenerates new token, invalidates old one, resets expiry
RevocationOwner-only; status set to REVOKED; token no longer valid

Invitation Status Lifecycle

PENDING → ACCEPTED (terminal)
PENDING → EXPIRED → PENDING (via resend)
PENDING → REVOKED → PENDING (via resend)
