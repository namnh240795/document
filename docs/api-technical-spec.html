5.2b Auth - Account Verification (Idempotent + Async)

POST /auth/send-verification (Requires: Authenticated) FR-012

Request account verification via email or SMS. Uses idempotency to prevent duplicate sends within 5 minutes. Verification is sent asynchronously via RabbitMQ.

Headers:

Authorization: Bearer <access_token>

Request:

{
  "channel": "sms"
}
// channel: "email" or "sms"

Response 200 (first request):

{
  "success": true,
  "data": {
    "message": "Verification sent successfully",
    "channel": "sms",
    "expiresIn": 300
  }
}

Response 200 (idempotent - already sent within 5 min):

{
  "success": true,
  "data": {
    "message": "Verification already sent. Please check your phone.",
    "channel": "sms",
    "alreadySent": true,
    "retryAfter": 240
  }
}

Error 429 (rate limited):

{
  "success": false,
  "error": {
    "code": "RATE_LIMITED",
    "message": "Please wait before requesting another verification",
    "retryAfter": 45
  }
}

Flow:

  1. API generates idempotency key: idempotency:{user_id}:{channel}
  2. Checks Redis for existing key
  3. If key exists: returns "already sent" (idempotent response)
  4. If no key: sets key in Redis with 5-min TTL
  5. Stores verification token in auth_verification
  6. Publishes event to RabbitMQ verification.{channel} queue
  7. Returns success immediately (async processing)

POST /auth/resend-verification (Requires: Authenticated) FR-013

Resend verification with rate limiting (1 request per 60 seconds). Invalidates previous verification token.

Headers:

Authorization: Bearer <access_token>

Request:

{
  "channel": "sms"
}

Response 200:

{
  "success": true,
  "data": {
    "message": "New verification sent successfully",
    "channel": "sms",
    "expiresIn": 300
  }
}

Response 429 (rate limited):

{
  "success": false,
  "error": {
    "code": "RATE_LIMITED",
    "message": "You can only resend once every 60 seconds",
    "retryAfter": 30
  }
}

Flow:

  1. Checks Redis rate limit key: resend_verify:{user_id}:{channel}
  2. If rate limit exceeded: returns 429
  3. Invalidates old verification token in auth_verification
  4. Follows same flow as send-verification (idempotency + RabbitMQ)

8. SDK & Integration Examples

cURL

# Register
curl -X POST https://api.example.com/v1/auth/sign-up \
  -H "Content-Type: application/json" \
  -d '{"name":"John","email":"john@example.com","password":"pass123"}'

# Login
curl -X POST https://api.example.com/v1/auth/sign-in \
  -H "Content-Type: application/json" \
  -d '{"identifier":"john@example.com","password":"pass123"}'

# Get users (with token)
curl https://api.example.com/v1/users \
  -H "Authorization: Bearer <token>"

NestJS Controller Example

@Controller('auth')
export class AuthController {
  constructor(private readonly authService: AuthService) {}

  @Post('sign-up')
  async signUp(@Body() dto: SignUpDto) {
    return this.authService.signUp(dto);
  }

  @Post('sign-in')
  async signIn(@Body() dto: SignInDto) {
    return this.authService.signIn(dto);
  }
}
